# Web Brand Growth

Create a coherent customer journey from brand promise to measurable action. Treat interface quality, code quality, search visibility, and marketing performance as one system.

## Route the task

- Read [references/brand-strategy.md](references/brand-strategy.md) for identity, positioning, messaging, tone, visual systems, or board/company pages.
- Read [references/seo-conversion.md](references/seo-conversion.md) for SEO, lead capture, analytics, campaign pages, attribution, or conversion work.
- Read [references/real-estate-web.md](references/real-estate-web.md) for property developers, projects, availability, execution photos, locations, or sales handoff.
- Read every applicable reference when the request spans multiple areas.

## Build workflow

1. Inspect the current product before changing it: stack, routes, assets, content, analytics, forms, APIs, deployment, and existing uncommitted work.
2. Separate verified facts from assumptions. Never invent prices, dates, people, titles, testimonials, project status, statistics, imagery provenance, or social profiles.
3. Define the primary audience, job-to-be-done, brand promise, proof, main CTA, and secondary CTA.
4. Design the information architecture before polishing components. Keep the home page selective and move depth to focused pages.
5. Establish reusable tokens for color, typography, spacing, radius, elevation, motion, and states. Reuse the real logo and approved assets.
6. Implement mobile-first with semantic HTML, predictable navigation, accessible forms, visible focus states, reduced-motion support, and touch targets near 44px or larger.
7. Protect speed. Prefer the lightest architecture that satisfies the interaction model; optimize critical images, fonts, JavaScript, and CSS before adding libraries.
8. Connect conversion actions to the real backend or CRM. Validate input, preserve attribution, show success and failure states, and keep a direct-call or WhatsApp fallback.
9. Add technical SEO: unique metadata, canonical URLs, crawlable links, structured data, sitemap coverage, social previews, and accurate entity information.
10. Add measurement for meaningful events: qualified lead, phone, WhatsApp, social visit, project filter, project interest, and form failure. Do not collect unnecessary personal data.
11. Verify responsive rendering, keyboard behavior, runtime errors, broken assets, content truthfulness, build output, and production deployment.

## Decision rules

- Prefer clarity over decorative density.
- Prefer real execution evidence over stock or unrelated renders.
- Label renders, construction progress, and completed work explicitly.
- Keep one dominant action per screen and maintain useful secondary paths.
- Do not add language toggles, accounts, reviews, integrations, or team identities that are not functional and verified.
- Do not migrate frameworks for prestige. Migrate only when it materially improves maintainability or the required product behavior.
- Keep SEO copy readable for people; never create keyword-stuffed or duplicate pages.
- Treat the CRM handoff and follow-up SLA as part of UX, not as a separate back-office concern.

## Handoff

Lead with what changed and where it is live. Report verification evidence, remaining factual inputs, and the next highest-impact opportunities. Distinguish completed work from recommendations.
