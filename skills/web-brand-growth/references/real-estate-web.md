# Real-estate website standards

## Project truth model

For every project keep a structured record for name/code, location, use, status, last verified date, imagery type, availability source, CRM identifier, and approved CTA. Treat missing data as unknown, not as permission to infer.

Label visual evidence explicitly:

- Architectural visualization.
- Actual construction progress with date when known.
- Completed project photography.
- Before/after comparison only when angles, subject, and stage are genuinely comparable.

Never use a render as a completed photograph or an unrelated photo as a project image.

## Discovery UX

Let visitors filter by location first when geography affects the buying decision, then property/use type and status. Keep filter state shareable in the URL. Project cards should expose the minimum decision set: name, location, use, status, evidence label, and next action.

Use individual project pages when enough verified content exists. Until then, provide reliable filtered listings and project-specific lead context.

## Trust and sales handoff

Show company identity, branches, official channels, process, execution evidence, privacy language, and leadership only when verified. Avoid fake urgency, unverified awards, anonymous testimonials presented as real, and fixed price claims that can expire.

Send project ID/name, unit type, budget range, campaign attribution, and referrer into the CRM. Confirm successful storage, route ownership correctly, and provide a visible failure fallback. Measure response time after submission as part of the customer experience.
